- Домен: vichkunina.art, дополнительный домен www.vichkunina.art.
- CDN-ресурс: bc8rzhym3xo5zktvheag.
- Каталог: b1gre1mo6s8ekc4bkqru.
- Провайдер: ourcdn.
- Выданный CNAME: f9b7003e54f211e9.topology.gslb.yccdn.ru.
- Источник: galleryvic.website.yandexcloud.net, HTTP.
- Время воспроизведения: 14 сентября 2026, примерно 20:38–20:49 МСК.

## Первые проверки (до включения Cloudflare для www)

В одном и том же чате Telegram:

1. https://storage.yandexcloud.net/galleryvic/share-check/cillian-v1.html — карточка с фотографией появляется.
2. https://vichkunina.art/share-check/cillian-v1.html — карточка не появляется.
3. https://www.vichkunina.art/share-check/cillian-v1.html — карточка не появляется.
4. https://github.com/vichkunina/gallery — карточка появляется.

Результаты подтверждены пользователем. Первые три адреса отдают один и тот же статичный HTML без JavaScript с корректным Content-Type text/html; charset=utf-8. Изображение в документе и og:image загружается напрямую из Object Storage: https://storage.yandexcloud.net/galleryvic/images/gallery/thumbs/48-img_5151.jpg (JPEG 960×960, 390653 байта).

Проблема затрагивает также старые ссылки на картины. @WebpageBot сообщает «Link previews was updated successfully. Check them out!», но превью не появляется.

## Уже проверено

- Локальные GET-запросы с User-Agent TelegramBot (like TwitterBot) возвращают HTTP 200 для страниц и картинок, загрузка занимает менее секунды. Это не проверяет сеть серверов Telegram.
- robots.txt разрешает все пути.
- Google Public DNS: домен и CNAME ресурса разрешаются в 188.72.103.4; AAAA отсутствует.
- Сертификат CDN в состоянии READY, профиль TLS PROFILE_COMPATIBLE.
- В ответе API настроек CDN не обнаружены настроенные IP-ограничения.
- Фотография и минимальная HTML-страница корректно обрабатываются Telegram при использовании прямого адреса Object Storage.

Прошу проверить запросы инфраструктуры Telegram к ресурсу, TLS, выбор CDN-узла/DNS и возможные ограничения на стороне провайдера. По имеющимся данным нельзя достоверно приписать блокировку Telegram или Yandex Cloud CDN.


## Последующие проверки 14 сентября 2026 (примерно 21:40–22:10 МСК)

Владелец включил Cloudflare Proxied только для www, SSL Full. Основной домен остался напрямую на Yandex CDN (188.72.103.4). www теперь 104.21.67.235 / 172.67.182.244. Содержимое бакета общее.

Подтверждённые владельцем результаты в Telegram:

| URL | Превью |
| --- | --- |
| https://www.vichkunina.art/share-check/cillian-route-v2.html | Есть |
| https://www.vichkunina.art/work/48/1/ | Нет |
| https://www.vichkunina.art/share-check/cillian-full-v3.html | Есть |
| https://vichkunina.art/share-check/cillian-full-v3.html | Есть |
| https://www.vichkunina.art/share-check/cillian-canonical-v4.html | Нет |

full-v3 — полная копия HTML картины с canonical и og:url на собственный адрес www, плюс noindex. canonical-v4 — полная копия с og:url на собственный адрес www, но canonical на https://vichkunina.art/work/48/1/.

Эксперименты на настоящей странице /work/48/1/:
- Только og:url изменён на www, canonical оставлен без www: превью нет, в том числе для ?share=4.
- И canonical, и og:url изменены на www: после обновления www-ссылки через @WebpageBot обычная ссылка без www всё равно без превью.
- Оба эксперимента отменены: canonical и og:url на настоящей странице снова без www.

Эти результаты не доказывают, что метатеги являются первопричиной: возможно влияние сохранённого состояния Telegram и повторного использования карточек по canonical/og:url. Подмена User-Agent в локальном запросе не воспроизводит инфраструктуру Telegram.

Дополнительные проверки:
- full-v3 отдаётся с apex и www побайтно одинаково: SHA256 c97709ce44a070baddbde446789d63070e514cfec04fe0625cd0a2ac62956e37.
- robots.txt разрешает Telegram. В Cloudflare добавлены правила для отдельных AI-ботов, но Telegram среди них не указан.
- TLS: leaf действует 2026-07-01—2026-09-29; YR2 → Root YR (cross-sign от 2026-05-13) → ISRG Root X1; OpenSSL проверяет цепочку успешно.
- Запросы из NL, US, DE и RU к диагностике через apex возвращали HTTP 200. Это также не доказывает доступ из сети Telegram.
- В конфигурации ресурса не обнаружена настройка экспорта журналов. Платный экспорт не включали.

## Что просим проверить

1. Видны ли реальные запросы Telegram к /work/48/1/ и /share-check/* за указанное время? Нужны время UTC, Host, URI, User-Agent, код HTTP, request_id и время ответа.
2. Есть ли ошибки TLS или ограничения на уровне сети/CDN до HTTP, которые не видны в настройках ресурса?
3. Различаются ли выбранные узлы или обработка запросов Telegram для /work/* и /share-check/*?
4. Если запросов нет, можно ли подтвердить это по доступным журналам и указать ограничения наблюдаемости?

Не просим менять DNS или перенаправлять сайт. Нужно установить, доходит ли запрос и что получает Telegram. Наличие рабочих тестовых карточек не позволяет объявить весь CDN недоступным. Обращение подготовлено, но не отправлено.


## Рабочий вариант и пределы проверки

После включения Cloudflare Proxied также для основного домена владелец подтвердил превью новой страницы apex-route-v5 без www. Старая /work/48/1/ всё ещё не показывала карточку. Для существующего адреса альбома https://vichkunina.art/work/48/ после установки canonical и og:url на этот адрес владелец подтвердил появление картинки.

В проекте закреплены адреса /work/{id}/ для обложек, canonical, sitemap и отправки ссылки. Адреса отдельных фотографий, включая старые /work/{id}/1/, продолжают открываться. Добавлена кнопка «Поделиться», передающая адрес альбома. Причина отрицательного состояния старых карточек не установлена; восстановление превью у всех старых отправленных ссылок не подтверждено. Реальная проверка Telegram подтверждена для альбома Киллиана; остальные картины проверены сборкой и валидатором HTML. Оригиналы фотографий не менялись.
